# Qwen 2.1：512 编辑 SmoothQuant＋ConvRot 验证

2026-10-28，基于合入 PR #15 后的 main `a5483add`。本次将分阶段图片编辑加速和编辑专用 SmoothQuant＋ConvRot 校准接入原生引擎、Swift 客户端和请求协议。默认关闭 SmoothQuant；它用于降低量化误差，不承诺进一步提速。

## 使用范围与实现

Apple M5 Pro / 24 GiB；512×512 画布、20–40 步、1–3 张快速 512 参考图、component_staged，使用与原始 BF16 checkpoint 匹配的固定 32-block / 1024-row / 6144-channel W8A8 ANE 分区。先开启 DiT W8A8，再开启 SmoothQuant＋ConvRot。LoRA、提示词增强、Runtime ANE、标准 1024 参考编码不进入此路线。

- 编辑按请求选择独立校准；文生图校准与已有缓存 key 不变。运行时不用外部校准文件，也不运行 Python。
- 使用人物改色、双图风格迁移、三图合成校准；1/2/3 张参考图、各 40 步、DBCache 关闭，完整覆盖 392 个投影和 1,925,440 个输入通道。狐狸、文字、静物三个评估样本未参与校准。
- 对跨样本 activation absmax 取最大值；alpha=0.5、scale 限制 [1/16,16]，保存 FP16 inverse，权重变换使用该保存值的精确倒数。复用现有 FP32 Hadamard 256/64 与真实 per-token A8 内核。
- 校准 identity：`a7f83254dc8bcb38b458175cfbc1c4f56433abf35239c7de40dab8e319446f8d`；payload SHA256：`338268d85b7daf922d35996455d37ced2238df74a5b5ec02eb73ee6bb6433b5a`。元数据包含校准提示词、种子、输入图与观察记录摘要；离线工具可逐字节重建提交的文件。
- 编辑 SQ 独立创建约 10.90 GiB 权重缓存；与普通 W8A8、文生图 SQ 均隔离，校验模型、配方、inverse 字节、张量形状/类型和 scale 有效性。切换时不会错误复用校准。
- ANE 精度由 manifest 决定。编辑不依赖“GPU 4 位权重缓存”开关；保存配置、恢复配置、生成结果转编辑和 Playground 模板保留兼容选项。

## 同参数画质比较

参考为相同 ANE、balanced DiT 缓存、参考图、提示词、seed=42、步数下的 BF16 DiT 输出。MAE 采用 0–255 RGB；SSIM 采用 11×11 / sigma=1.5 Gaussian population moments。数值表示与参考更接近，不是通用画质评分。

| 样本 | MAE，普通 W8A8 → 编辑 SQ | SSIM，普通 W8A8 → 编辑 SQ |
|---|---:|---:|
| 狐狸改蓝，20 步 | 2.8808 → 1.1603 | 0.987192 → 0.996889 |
| 文字改红，20 步 | 0.6649 → 0.1512 | 0.995837 → 0.998828 |
| 杯子改绿，40 步 | 0.5168 → 0.2164 | 0.995267 → 0.997824 |

目视检查：三个方案均完成指定改色；文字保持 BLUE SKY，杯子变绿且红方块/黄球保留，狐狸姿态和雪景可辨。狐狸和雪景本身仍有模型编辑带来的细节变化。双图合成成功将蓝杯放到狐狸旁；三图合成进一步加入 BLUE SKY 标牌。这两项验证功能和图像内容，没有对应浮点质量基线。

## 打包客户端耗时

同一狐狸图、提示词、seed=42、20 步，固定 ANE＋balanced DiT 缓存＋DiT W8A8，只切换 SmoothQuant＋ConvRot。三轮交换执行顺序，每个组合先预热再重复一次；计时期间无编译或其他模型验证。使用实际打包 App 的原生 API，不计 UI 与引擎创建。

| 组合 | 请求耗时中位数 | 三次范围 |
|---|---:|---:|
| ANE＋缓存＋DiT W8A8 | 18.197 s | 18.150–18.231 s |
| 再开编辑 SmoothQuant＋ConvRot | 21.128 s | 19.005–23.547 s |

本机该样本耗时变化为 +16.1%。两组均使用已存在的磁盘缓存，392 个投影全部命中，重复请求的编码缓存命中；各组合重复输出一致。保持默认关闭，优先速度时用普通 DiT W8A8，需要更贴近浮点参考时再打开。

## 回归与限制

原生/Swift 构建、完整 `make test-app` 与 `make test-library`、Qwen 工作流/Playground 保存恢复、149 项请求契约（146 通过、3 项依赖夹具跳过）、13 项 CLI 覆盖、4 项冻结校准检查通过。真实 Metal 小矩阵验证了两种校准、长序列、compiled/eager 等价、缓存损坏拒绝及取消。

实机文本编码和去噪阶段取消均返回取消状态且无输出；随后重试与再次开启 SQ 的 PNG 一致。关闭 SQ 恢复普通 W8A8 的原输出。每次恢复调用者 256 MiB wired 设置，取消/完成后 MLX active 小于 256 MiB。文生图使用原校准，适配前后相同图像参数的输出 PNG 逐字节一致。双/三参考图分别实际生成 20/40 步，所有成功运行 Core ML 失败数为零。

Qwen 全套中两项已有数值检查失败：原始 ConvRot F32 coefficient 参考误差、small-GEMM 历史反例不再产生差异。它们在适配前客户端库同样复现，未放宽断言；另一个默认 SDK 路径过时的检查，在设置当前 `SDKROOT` 后通过。全量 `make test` 最终结果见下方机器记录，不能据此声称整个仓库全绿。

只有三个单种子画质样本；耗时受桌面负载和已有 swap 影响。MLX 峰值不含 Core ML/系统/文件缓存，未观测实际 ANE 驻留。首次生成约 11 GiB 编辑 SQ 缓存的成本不计入热缓存速度。

完整数值、输入摘要、构建摘要、运行回执与测试限制见 [机器记录](../design/validation/qwen21-edit-smoothquant-2026-10-28.json)。原图、输出图、完整请求与本地脚本保存在未跟踪的 `local-experiments/qwen21-edit-sq-20261028/`，未将模型或个人路径提交到源码。
